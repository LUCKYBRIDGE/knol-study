# 제품 포렌식 분석 — 구조보다 한 단계 더 깊게

검토일: 2026-11-08

`docs/structure/`가 **무엇이 어디에 있는지**를 설명한다면, 이 디렉터리는 **왜 그런 구조가 생겼고 어떤 사용자·기술 문제를 어떤 메커니즘으로 풀었는지**를 분석한다.

## 분석 질문

각 제품마다 다음을 묻는다.

1. 제품이 가장 어렵게 푸는 문제는 무엇인가?
2. 사용자는 어떤 흐름으로 그 문제를 해결하는가?
3. 내부에서는 그 행동을 어떤 명령·상태·데이터로 표현하는가?
4. 일시 상태와 영속 상태를 어떻게 구분하는가?
5. 저장·복구·동기화에서 무엇을 신뢰의 원천으로 삼는가?
6. 기능을 늘릴 때 core를 어떻게 보호하는가?
7. 잘못된 상태와 네트워크 실패를 어디에서 막는가?
8. 사용성이 복잡해질 때 어떤 UX 원칙으로 제어하는가?
9. 테스트는 어떤 실패를 가장 두려워하는지 보여주는가?
10. 이 설계의 장점이 만들어내는 비용은 무엇인가?
