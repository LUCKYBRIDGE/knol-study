# Artsteps — 3D 전시 UX 심층 검토

검토일: 2026-11-08. **공식 사이트가 안내하는 제작 단계와 기능만 직접 확인(A). 실제 전시실 조작·성능·모바일 동작 실측은 미실시.**

## 1. Artsteps에서 실제 확인되는 흐름
[공식 Artsteps](https://www.artsteps.com/)가 안내하는 핵심 제작 흐름은:
1. 사진·영상·텍스트·3D 객체 업로드(음악·내레이션도 포함).
2. 벽·색·텍스처·가상 공간 구성.
3. guide point를 배치해 관람객에게 narrative를 제공.
4. 결과물을 웹 공유·embed.

이는 **콘텐츠 자산 → 공간 구조 → 관람 스토리 → 배포**라는 저작 모델이다. 현재 Artsteps가 사용하는 카메라 제어 세부 알고리즘, 충돌 처리, 모바일 조이스틱 구조, 가이드 포인트 자동 이동 여부는 공식 소개만으로 확정할 수 없다.

## 2. 놀아트의 사용자 역할을 분리
| 역할 | 목표 | 필요한 인터페이스 |
|---|---|---|
| 전시 제작 교사 | 작품을 빠르게 배치 | 일괄 업로드·자동 벽 배치·순서 설정 |
| 학생 제작자 | 자기 작품 소개 | 제목·설명·작가표시·작품 미리보기 |
| 관람 학생 | 쉽게 감상 | 다음 작품·이전 작품·설명 보기 |
| 학부모 방문자 | 로그인 없이 관람 | 직관적 진입·로딩 안내·모바일 최적화 |

교사와 관람객에게 같은 3D 조작기능을 제공하려 하지 않는다.

## 3. Guided Tour의 자체 구현 제안
```ts
type Exhibit = { id: string; assetId: string; wallId: string; displayTransform: Transform; label: string; };
type Viewpoint = { exhibitId: string; eye: Vec3; lookAt: Vec3; durationMs: number; };
type Tour = { orderedViewpoints: Viewpoint[]; allowFreeRoam: boolean; };
```
위 구조는 Artsteps 내부 포맷이 아니라 **놀아트 설계 제안**이다.

### 왜 카메라 위치를 작품 위치와 따로 보존해야 하나
액자 중심 좌표만 있으면 이동 목표를 계산할 수 있어도 관람자가 너무 가까이 서거나 비스듬히 볼 수 있다. 감상용 eye/lookAt을 사전 계산·저장하면 다음/이전 이동과 반자동 투어가 안정적이다.

### 카메라 이동 품질 가이드(실험 값, 제품 사실 아님)
- 시작/종료 지점 easing.
- 작품 앞에서 최소 감상 거리 확보.
- 벽 관통이 발생하면 spline 대신 안전한 waypoint 이용.
- 이동 중 사용자 직접 조작 시 투어를 취소할지 일시정지할지 명확화.
- 멀미를 줄이기 위해 급격한 yaw·pitch와 자동 카메라 가속 제한.
- reduce-motion 설정 시 애니메이션 없이 즉시 이동 가능.

## 4. 입력 모드별 설계
**PC**
- 이동: WASD/방향키 중 택일, 도움말.
- 회전: 명시적으로 드래그할 때만; 마우스 포인터 lock을 강제하지 않음.
- 상호작용: 작품 가까이 접근 → 선택 강조 → 작품 카드.

**태블릿**
- 좌측 이동 패드, 우측 터치 카메라와 UI 버튼의 영역 분리.
- 두 손가락 gesture와 페이지 스크롤 간 충돌 검사.
- 작은 조이스틱보다 **이전/다음** 버튼을 반드시 제공.

**접근성 대체 경로**
- 3D 조작 없이 목록/그리드에서도 모든 작품 열람.
- 키보드 포커스와 작품 설명 대체 텍스트 제공.
- WebGL 불가 시 2D 전시 목록으로 fallback.

## 5. 교사 중심 전시 제작 UX
1. 일괄 작품 추가.
2. 자동 배치(작품 비율/벽 폭/간격 고려).
3. 카드 목록에서 전시 순서를 변경.
4. 전시실 미리보기.
5. 한 번의 공유 동작으로 관람 링크 생성.

### 알고리즘 실험
- 벽 별 usable width에 작품 frame width + margin 합을 배치.
- 1차원 bin packing으로 벽별 분산 후 사용자가 drag reorder.
- 오버랩/벽 밖 배치/작품 뒤집힘 자동 검출.
- 텍스처는 리사이즈·mipmap·lazy loading으로 GPU 메모리 제어.
- 작품 자산의 원본/전시용 thumbnail 분리.

## 6. 테스트 시나리오
| 상황 | 성공 기준 |
|---|---|
| 25개 작품 업로드 | 수동 25회 배치 없이 전시 생성 |
| 작품 1→25 | 키보드 이동 없이 모든 작품 도달 |
| 저사양 태블릿 | WebGL 부족 시 기능 안내 또는 2D fallback |
| 카메라 충돌 | 벽/액자 내부로 진입하지 않음 |
| 작품 클릭 | 정확히 액자를 누르기 어렵더라도 작품 선택 가능 |
| 저시력·멀미 | 애니메이션 줄이기, 카드 목록 대체 경로 |
| 공유 | 관람자는 편집 권한을 얻지 않음 |

## 7. 확인과 미확인의 경계
- **확인**: guide points, 공간/콘텐츠/서사 구성, 공유·임베드.
- **미확인**: Artsteps 실제 자유 이동과 안내 이동의 UI 조합, 관람 시 이동 보간 방식, 입력장치별 성능·상세 동작.
- **우리 제안**: guided tour, auto-placement, 방문 체크, 미니맵, teleport, 접근성 fallback.

따라서 'Artsteps와 동일하게 구현했다'가 아니라 'Artsteps의 guide point 개념을 참고해 놀아트용 관람 UX를 설계했다'고 표현해야 정확하다.

**결론**: 새 캐릭터보다 관람 경로·카메라 안정성·2D 접근성 대안을 먼저 구현한다.
